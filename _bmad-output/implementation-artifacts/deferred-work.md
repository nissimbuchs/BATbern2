## Deferred from: code review of 11-b-2-speakerworkflowservice-sole-status-writer (2026-05-16)

- **Side-effect hooks fire emails + external HTTP before commit** [`SpeakerWorkflowService.java` `runInvitedHook` / `runAcceptedHook` / `runReadyHook`] — `runInvitedHook` sends the invitation email inside the `@Transactional` boundary; if a downstream operation rolls back, the email is already gone. Initial code-review fix wired `TransactionSynchronizationManager.afterCommit` but had to be reverted: 5 `SpeakerWorkflowServiceIntegrationTest` cases assert on the email/organizer-notify mocks under `@Transactional` rollback semantics, where after-commit callbacks never fire. Follow-up needs: (a) wire AFTER_COMMIT via either a domain-event listener (`SpeakerInvitedEvent` / `SpeakerAcceptedEvent` consumed by `@TransactionalEventListener(phase = AFTER_COMMIT)`) or `TransactionSynchronizationManager` in the service; (b) update the affected integration tests to commit the transaction (`TestTransaction.flagForCommit()` or `@Sql(executionPhase = ...)`); (c) restore the after-commit symmetry for runDeclinedHook's organizer notify.
- **Slot-capacity TOCTOU race + concurrent `sendInvitation` race** [`SpeakerWorkflowService.java:201-209`, `SpeakerInvitationService.java:165-217`] — `enforceSlotCapacity` reads `count(ACCEPTED) + count(INVITED)` without a row/event lock and `SpeakerPool` has no `@Version`. Two concurrent `READY → INVITED` callers can both pass the gate and both commit; two concurrent `sendInvitation` calls on the same speaker can each generate magic-link tokens. Explicitly accepted by PM Resolved Decision #6 ("race window matches current behaviour"). Future story should add `@Lock(LockModeType.PESSIMISTIC_WRITE)` on `speakerPoolRepository.findById(...)` inside `transition()` and a uniqueness constraint or `@Version` on `SpeakerPool`.
- **`runDeclinedHook` deletes session without checking co-presenters** [`SpeakerWorkflowService.java:268-275`] — `sessionRepository.deleteById(sessionId)` runs unconditionally for post-invitation declines. Pre-existing behaviour from the deleted `SpeakerStatusService.updateStatus`. If multiple `SpeakerPool` rows share a `sessionId` (panels), the other speakers end up with orphaned `session_id` FKs. Track in a follow-up story for multi-speaker session handling — at minimum, `findBySessionId(sessionId).size() > 1 ? clearLink : delete` would close the obvious hole.
- **Coverage gaps in new test suite** [`SpeakerInvitationServiceTest`, `SpeakerWorkflowServiceTest`, `SpeakerWorkflowServiceIntegrationTest`] — missing: explicit `RESPOND` + `VIEW` `TokenAction` assertion in invited-hook test; `READY → DECLINED` and `CONTACTED → DECLINED` paths (no reason required, no organizer notify); spec-named `should_notReFireSessionAutoCreation_when_acceptedToAcceptedSameStateTransition()` (covered structurally but not by name); panel-session-delete regression. Coverage target (≥90%) is met (91.8%); these are dark scenarios rather than gaps in line coverage.
- **`firstNameFallback` / `lastNameFallback` literals "Speaker" / "Unknown"** [`SpeakerWorkflowService.java:367-379`] — when payload omits name and `speakerName` is blank, the new User has `firstName=Speaker, lastName=Unknown`. Becomes Cognito user attributes in Phase E (Story 11.E.2 owns the welcome-email rendering and should decide whether to (a) reject the transition at the seam, (b) require name on `TransitionPayload` for `CONTACTED → READY`, or (c) accept the placeholder and let the welcome email render around it).
- **`resolveLocale` accepts arbitrary garbage** [`SpeakerWorkflowService.java:355-365`] — `Locale.forLanguageTag("xyz123")` silently returns an empty-language locale; email template falls back to service default. Pure observability concern (debug-time mystery for translators); not user-facing.
- **`enforceSlotCapacity` N+1 on batch invites** [`SpeakerWorkflowService.java:201-209`] — each `transition` to INVITED issues `eventTypeService.getEventType(...)` + two `countByEventIdAndStatus` queries. `3N` round-trips for batch-invite. Revisit if/when batch-invite becomes a hot path; can be cached per `event.eventType` for the duration of a request or replaced with a single aggregate query.
- **`MagicLinkService.RESPONDED_STATES` interaction with legacy DB rows** [`MagicLinkService.java:65-69`] — new set `{ACCEPTED, DECLINED, CONTENT_SUBMITTED, QUALITY_REVIEWED}` excludes the legacy `CONFIRMED` / `SLOT_ASSIGNED` values. A legacy `CONFIRMED` row would let the magic-link respond form re-open for an already-committed speaker. Gated on Story 11.B.3 Flyway migration; 11.B.3 should also include a post-migration assertion that no row holds a legacy value.
