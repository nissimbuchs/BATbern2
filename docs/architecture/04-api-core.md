# Core API Conventions

**Last Updated**: 2026-11-20
**ADR References**: [ADR-003: Meaningful Identifiers in Public APIs](./ADR-003-meaningful-identifiers-public-apis.md),
[ADR-008: Simplified API Gateway Routing](./ADR-008-simplified-api-gateway-routing.md) (roles checked in the services),
[ADR-013: REST API CRUD Conventions](./ADR-013-rest-api-crud-conventions.md)

The conventions every public BATbern API shares. The operations themselves are defined in the
OpenAPI specs in `docs/api/*.openapi.yml` (index: [04-api-design.md](./04-api-design.md)); the
specs are the source of truth, and code is generated from them (ADR-006).

## Base URL and versioning

| Environment | Base URL |
|---|---|
| Production | `https://api.batbern.ch/api/v1` |
| Local development | `http://localhost:8000/api/v1` (API gateway, `BASE_PORT` 8000 by default) |

There is no separate staging API: the staging AWS account serves production. All public paths
carry the version prefix `/api/v1`. Service-to-service operations live under `/internal/**`
(specs in `docs/api/internal/`); the gateway does not route them.

## Authentication and authorization

- `Authorization: Bearer {token}`: a Cognito-issued JWT; the role is in the `custom:role` claim
  (Watch tokens carry it in `role`).
- The gateway authenticates the token and routes; roles are checked in the services
  (`@PreAuthorize` on every write endpoint, ADR-008).

## Headers

| Header | Direction | Meaning |
|---|---|---|
| `X-Correlation-ID` | request and response | Taken from the request, generated by the gateway when absent, echoed on the response and put in the log MDC (`CorrelationIdFilter`) |
| `X-RateLimit-Limit` | response | Per-minute limit of the caller's role |
| `X-RateLimit-Remaining` | response | Requests left in the current window |
| `X-RateLimit-Reset` | response | Start of the next minute, epoch milliseconds |

## Rate limiting

Enforced by the Spring API gateway (`RateLimitingFilter`, `RateLimiter`,
`InMemoryRateLimitStorage`). Counters are kept in memory per gateway instance, per caller and
per request path, in a 1-minute window. An authenticated caller is counted by the JWT subject
and the first role in its role claim (default `attendee`); an anonymous caller by client IP.

| Role | Requests per minute |
|---|---|
| organizer | 1000 |
| speaker | 500 |
| partner | 500 |
| attendee | 200 |
| anonymous (per IP) | 50 |
| any other role | 10 |

Anonymous POSTs that send mail have their own per-IP limit, counted instead of the anonymous
limit above:

| Endpoint | Limit |
|---|---|
| `POST /api/v1/events/*/registrations` | 5 per 5 minutes |
| `POST /api/v1/newsletter/subscribers` | 5 per 5 minutes |
| `POST /api/v1/registrations/deregister/by-email` | 3 per 5 minutes |

`InMemoryRateLimitStorage` also defines burst limits per 10 seconds, but no request path checks
them today. The event-management service adds its own per-IP limit of 10 per minute on
`POST /api/v1/events/{eventCode}/registrations` (`RateLimitFilter`, not active in the `test`
profile).

An exceeded limit answers `429 Too Many Requests` with a JSON body that carries `limit` and
`retryAfter` (seconds); no `Retry-After` header is set.

## Errors

Errors use the flat `ErrorResponse` envelope (`timestamp`, `path`, `status`, `error`,
`errorCode`, `message`, `correlationId`, `severity`, `details`; absent fields are omitted).
Its single definition is [`docs/api/_shared.openapi.yml`](../api/_shared.openapi.yml), backed by
`ch.batbern.shared.dto.ErrorResponse` (ADR-013 §6).

## Lists: pagination, sort, filter

All list endpoints use **page-based** pagination (not offset or cursor):
- `page`: page number, 1-based (default 1; `PaginationUtils.parseParams`)
- `limit`: items per page (default 20, capped at 100)
- `sort`, `filter`: JSON:API-style expressions (ADR-013 §3)

List endpoints always sort by a unique tie-breaker (`id`) after the requested sort, so pages
neither repeat nor drop rows when the sort key has ties. Build every `Pageable` with
`ch.batbern.shared.api.DeterministicPaging`; `DeterministicPagingGuardTest` fails the build on a
raw `PageRequest.of` (#1131).

The response wraps the items in a `PaginatedResponse` with `PaginationMetadata`
(`_shared.openapi.yml`, `ch.batbern.shared.api.PaginationMetadata`):

```json
{
  "data": [...],
  "pagination": {
    "page": 1,
    "limit": 20,
    "totalItems": 150,
    "totalPages": 8,
    "hasNext": true,
    "hasPrev": false
  }
}
```

## Identifiers

Top-level resources use meaningful identifiers in the path (`eventCode`, `username`,
`companyName`, `topicCode`); UUIDs only for transient or internal sub-resources such as photos,
posts, uploads, meetings and notes (ADR-003, narrowed by ADR-013 §5).
