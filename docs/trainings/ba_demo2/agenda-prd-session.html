Step 4: Vision Discovery

The agent probes for what makes this product special

User Prompt
c
Agent Response (John) — Vision Questions

"We've established this is a brownfield web app in event management / community governance with medium complexity. Now let's get to the WHY."

What I think the core insight is:

"The partner meeting already happens. Six agenda items already get covered. Votes already happen (verbally). Notes already get taken (by someone, hopefully). But none of it leaves the room in a structured, traceable way. The meeting is a black box."

"The breakthrough here isn't 'build a meeting tool.' It's: make the meeting document itself as a byproduct of running it."

Three sharpening questions:

  1. What's the real cost of the current approach? Efficiency issue or governance/accountability gap?
  2. Who's the primary champion? Organizer wanting better meetings or partners wanting transparency?
  3. What would make the organizer say "I can't go back to the old way"?
Training Note

Notice how John is a facilitator, not a template-filler. He synthesized the core insight from the brainstorming docs and asked targeted "WHY" questions. In a normal session, you'd answer these questions. But since all the information was already in the brainstorming and UX spec, we accelerated:

Step 5: Autonomous PRD Generation

Instructing the agent to fill all remaining sections from loaded documents

User Prompt

Key Teaching Moment

This is a power-user move. The normal workflow has 12 steps with a review cycle at each step. But when your input documents are comprehensive (we had a detailed brainstorming session + a complete UX spec), you can instruct the agent to drive autonomously and only interrupt when something is genuinely unclear.

Takeaways for Business Analysts

Key lessons from this PRD creation session

📄 Input Quality = Output Quality

The PRD was strong because the inputs were strong. A detailed brainstorming session (35 ideas, prioritized) and a comprehensive UX spec (5 journeys, 12 components) gave the PM agent everything it needed. Garbage in, garbage out — invest in your analysis phase.

🎯 Point to Specific Files

When the agent auto-discovered the wrong files, we redirected it to the exact files we wanted. Don't let the agent guess — be explicit about your inputs. read 'path/to/file.md' is your friend.

⚡ Know When to Accelerate

The workflow has 12 interactive steps. When your inputs are comprehensive, you can tell the agent: "fill in all chapters, only ask when unclear." This collapsed 10 review cycles into a single generation pass. Use this when you trust your inputs.

🔍 The Agent Asks WHY

John didn't just fill a template. He identified the core insight ("the meeting documents itself") and asked three sharpening questions. Even when you accelerate, the vision discovery step ensures the PRD captures why the product matters, not just what it does.

🔗 Artifacts Chain Together

Brainstorming → UX Spec → PRD. Each artifact builds on the previous one. The PRD's functional requirements map directly to brainstorming ideas. The user journeys come from the UX spec. The scope phases match the brainstorming's 4-layer build order. This traceability is the BMAD advantage.

📋 Review the Classification

The project classification (type, domain, complexity, context) shapes everything downstream. It determines which PRD sections are relevant, which NFRs matter, and whether domain-specific steps run. Always validate the classification before continuing.
