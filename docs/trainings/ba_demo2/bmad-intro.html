What is the BMAD Method?

AI agents that think like your team — analyst, PM, architect, designer, developer

The BMAD Method (BMM) is a modular AI framework that provides specialized agents for every phase of software development. Instead of one generic AI assistant, you get purpose-built agents — each with a distinct persona, expertise, and structured workflows — that produce traceable artifacts feeding into the next phase.

🤖

Specialized Agents

7 default agents, each with a name, personality, and domain expertise. They don't just answer questions — they facilitate structured workflows.

🔄

Progressive Phases

4 phases where each artifact feeds the next. Analysis informs Planning, Planning drives Solutioning, Solutioning guides Implementation.

📄

Traceable Artifacts

Every phase produces markdown documents. A brainstorming report feeds the PRD. The PRD feeds architecture. Architecture feeds stories. Nothing is lost.

⚙️

Adaptive Complexity

From a quick bug fix (/bmad-quick-dev) to an enterprise platform with 10+ epics — the framework scales to your project's needs.

Key Principle: Vague thinking produces vague requirements, which compounds into weak architecture and incomplete stories. BMAD's structured phases prevent this compounding by forcing clarity at each stage before moving forward.

How Workflows Work

Step-by-step facilitated processes with review cycles

1. Activate an Agent

Type the slash command. The agent greets you, loads the project config, and shows a menu of available workflows.

Example: /bmad-agent-bmm-pm → John presents: Create PRD, Validate PRD, Create Epics, etc.

2. Select a Workflow

Choose a menu item (e.g., "CP" for Create PRD). The agent loads a multi-step workflow and begins with Step 1.

Example: PRD workflow has 12 steps: Init → Discovery → Vision → Executive Summary → ...

3. Collaborative Discovery

The agent asks questions, synthesizes your answers, and drafts content. It auto-discovers input documents from previous phases.

Key: The agent is a facilitator, not a template filler. It asks "WHY?" and probes deeper.

4. Review & Continue

After each step, the agent presents its work and offers: [A] Advanced Elicitation, [P] Party Mode, [C] Continue. You review, refine, and approve.

Power move: When inputs are comprehensive, tell the agent to drive autonomously.

Quick Start for Business Analysts

Your role focuses on Phases 1-3

As a BA, your primary BMAD workflows are in Analysis (brainstorming, research, briefs), Planning (PRD, UX), and Solutioning (architecture review, epics). Here's how to get started:

Step 1: Brainstorm

Activate Mary: /bmad-agent-bmm-analyst

Select [BP] Brainstorm Project

Describe your problem space. Mary guides you through structured techniques (morphological analysis, role playing, cross-pollination) to systematically discover features.

Output: Prioritized feature inventory

Step 2: Create UX Spec

Activate Sally: /bmad-agent-bmm-ux-designer

Select [CU] Create UX Design

Sally reads your brainstorming output and facilitates UX decisions: user journeys, interaction patterns, design system, accessibility.

Output: UX Specification

Step 3: Create PRD

Activate John: /bmad-agent-bmm-pm

Select [CP] Create PRD

John synthesizes brainstorming + UX into a 12-section PRD with functional requirements, success criteria, scope, and phasing.

Output: Product Requirements Document

Step 4: Architecture & Epics

Activate Winston: /bmad-agent-bmm-architect

Then John for [CE] Create Epics

Winston designs the technical solution. John breaks the PRD into implementable epics and stories. Run [IR] Implementation Readiness as the final gate.

Output: Architecture + Epic files
